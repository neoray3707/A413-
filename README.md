## 1. 我理解的任务

这次任务是用 PyTorch 训练一个 MNIST 手写数字识别模型，并把代码上传到自己的
Git 仓库。和平时直接调库不同，作业要求不能使用第三方封装好的数据集接口，
所以 MNIST 的四个原始文件需要自己读取、解析和预处理。

除了把模型跑通，我还需要说明模型结构、训练过程，以及自己在做这个任务时的
真实感受。测试集结果不能拿来反复调参，否则最后的准确率就不可信了。

## 2. 数据与预处理

MNIST 官方提供四个文件：训练图像 60000 张、训练标签 60000 个、测试图像
10000 张、测试标签 10000 个。图像是 28×28 的灰度图，标签是 0~9。

这些文件是 IDX 二进制格式，不是普通的 PNG/JPG。图像文件的前 16 个字节是
文件头，包含 magic number、图像数量、行数和列数；标签文件的前 8 个字节是
文件头和标签数量。所有整数都是大端序，所以读取时要按大端序解析。

读取之后，我做了三件事：

1. 把像素转成 `float32` 并除以 255，缩放到 0~1；
2. 增加通道维，把形状从 `(N, 28, 28)` 变成 `(N, 1, 28, 28)`；
3. 用 MNIST 的均值 0.1307、标准差 0.3081 做标准化。

训练集我没有全部用来训练，而是按类别分层切出了 6000 张作为验证集，最后得到
54000 张训练图、6000 张验证图、10000 张测试图。验证集用来选模型，测试集只在
最后评估一次。训练时还做了 ±2 像素的随机平移，验证集和测试集不做增强。

## 3. 模型结构

模型是一个小型卷积神经网络，输入是 `1×28×28`，输出是 10 个 logits。

| 阶段 | 操作 | 输出形状 |
| --- | --- | --- |
| 输入 | 灰度图 | `B×1×28×28` |
| Block 1 | Conv 3×3（1→32）+ BN + ReLU | `B×32×28×28` |
| Block 1 | Conv 3×3（32→32）+ BN + ReLU | `B×32×28×28` |
| Pool 1 | 2×2 最大池化 | `B×32×14×14` |
| Block 2 | Conv 3×3（32→64）+ BN + ReLU | `B×64×14×14` |
| Block 2 | Conv 3×3（64→64）+ BN + ReLU | `B×64×14×14` |
| Pool 2 | 2×2 最大池化 | `B×64×7×7` |
| Flatten | 拉平 | `B×3136` |
| FC 1 | 3136→128，BN + ReLU + Dropout | `B×128` |
| FC 2 | 128→10 | `B×10` |

两个卷积块后面都有 Dropout，第一个卷积块的 Dropout 是 0.25，全连接层前是 0.5。
整个模型一共有 468266 个可训练参数。

这样设计主要有三个原因：两个 3×3 卷积串联可以得到接近 5×5 的感受野，但参数
更少；BatchNorm 让训练更稳定，收敛更快；Dropout 可以减轻过拟合。池化则负责
把特征图从 28×28 降到 7×7，减少后面的计算量。

## 4. 训练过程

训练用的主要参数如下：

| 项目 | 设置 |
| --- | --- |
| Batch size | 128 |
| Epochs | 10 |
| 优化器 | AdamW |
| 初始学习率 | 1e-3 |
| 权重衰减 | 1e-4 |
| 学习率调度 | CosineAnnealingLR，最低 1e-5 |
| 损失函数 | CrossEntropyLoss，label smoothing = 0.05 |
| 数据增强 | 随机平移 ±2 像素（仅训练集） |
| 梯度裁剪 | 1.0 |
| 混合精度 | CUDA 上开启 AMP |
| 随机种子 | 42 |

每个 epoch 的流程是：打乱训练集，按 batch 取图和标签；前向传播得到 10 个
logits；计算交叉熵损失；反向传播并更新参数；然后在验证集上计算 loss 和
accuracy。如果验证集准确率比之前高，就保存当前模型；如果准确率相同，则比较
loss，取 loss 更小的。学习率每轮按余弦曲线下降。连续 5 轮验证集没有提升就
提前停止。

最后我加载验证集上最好的模型，在测试集上评估一次。最佳验证集准确率是
99.38%，出现在第 9 轮；测试集准确率是 99.54%。

## 6. 我遇到的问题

第一个问题是数据读取。以前用现成的数据集接口时，我根本没有关心过文件是
怎么存的。这次看到 IDX 文件头、大端序这些概念，一开始有点懵。后来我先打印
magic number、图像数量、形状和像素范围，确认数据读对了，才继续训练。

第二个问题是训练准确率和验证准确率的关系。我第一次看到训练准确率比验证
准确率低时，以为模型有问题。后来才知道训练时开了 Dropout、随机平移和 label
smoothing，而验证时这些都关闭了，所以训练准确率低一点是正常的。

第三个问题是不要一上来就跑完整训练。先用 `--limit-batches` 跑几个 batch，
确认数据形状、loss、保存和画图都正常，再跑 10 轮，排查起来会快很多。

## 7. 我的感悟

这次任务让我对“训练一个模型”有了更完整的认识。以前我觉得只要把网络搭好、
把数据丢进去就行，真正做完才发现，数据读取、训练集/验证集/测试集的划分、
模型保存、结果分析，每一步都有很多细节。

我印象最深的是验证集的作用。最开始我想直接用测试集看效果，后来意识到这样会
不自觉地根据测试集调参，最后得到的准确率就不可信了。改成 54000/6000 的划分
之后，所有参数只看验证集，测试集只在最后用一次，99.54% 这个结果我才比较放心。

对 BatchNorm 和 Dropout 的理解也比以前具体了。BatchNorm 不只是“加一层”，
它让每层的输入分布更稳定，所以可以用更大的学习率；Dropout 只在训练时随机
丢弃神经元，推理时要关掉，所以评估前必须调用 `model.eval()`。这些以前只是
背概念，这次通过看训练日志和代码，理解得更清楚了。

还有一个体会是“先小步验证”。不要等 10 轮跑完才发现保存路径错了或者图画错了。
先用几个 batch 把整条流程跑通，再逐步增加训练量，效率会高很多。

这个模型还比较基础，下一步我想尝试学习率 warmup、更强的数据增强，或者把模型
导出成 ONNX 做一个简单的手写数字网页 Demo。现在的结果不算完美，但整个流程
是我自己跑通的，这比单纯追求高准确率更有收获。
